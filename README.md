# Итоговый проект: сравнение продаж магазина и конкурентов

Пайплайн загружает заказы, активности и `customer_research` из API,
очищает данные, наполняет хранилище по схеме «Звезда» и собирает
`rep.market_share_report` с долей магазина по количеству товаров и выручке.

## Структура

- `scripts/DDL_*.sql` — создание схем, таблиц, ключей и ограничений.
- `scripts/SQL_*.sql` — загрузка слоёв, расчёт витрины и сверка.
- `dags/migrations/` — те же DDL с числовыми именами для `db_migrator`.
- `dags/sql/` — те же DML с именами, используемыми операторами Airflow.
- `dags/data_models/` — Pydantic-модели ответа API.
- `dags/repository/` — интерфейс репозитория и реализация PostgreSQL.
- `dags/utils/api_config.py` — получение XCom и парсинг.
- `dags/datasets/` — датасеты для запуска витрины.
- `tests/` — Python-тесты, PostgreSQL-тесты, фикстуры и тестовые данные.

SQL в `scripts` и соответствующих папках `dags` совпадает; первая папка
предоставляет скрипты для просмотра, вторая используется при запуске DAG.

## Порядок заполнения таблиц

1. `db_migrator` создаёт `meta.table_info` и применяет версии
   `000 → 001 → 008 → 009 → 010 → 011`. Пропуски номеров допустимы:
   мигратор обрабатывает существующие SQL-файлы по возрастанию версии.
2. `api_data_load` проверяет API и загружает три источника в RAW.
   Перед повторной загрузкой очищаются записи за логическую дату.
3. `datamarts_load` ждёт завершения исходных задач через `ExternalTaskSensor`,
   очищает дневной срез ODS, удаляет дубли и загружает ODS.
4. Обновляются STG и измерения `cdm.d_customer`, `cdm.d_city`, `cdm.d_item`.
5. Загружаются факты `cdm.f_order`, `cdm.f_activity`, `cdm.f_customer_research`.
   Город конкурентов связывается с `d_city.id` с учётом периода действия записи.
6. После обновления датасетов `f_order` и `f_customer_research` DAG
   `load_market_share` рассчитывает витрину. Он суммирует все категории
   за дату и город и обновляет строку по ключу `(date_time, city_id)`.

Формула доли: `наши продажи / (наши продажи + продажи конкурентов)`.
Используется дробное деление; при нулевом знаменателе результат NULL.
Повторный расчёт выполняет UPSERT и не создаёт дублей витрины.

## Запуск

Используется Airflow 2.10.3. Проект запускается через Docker Compose.
Создайте локальный `af.env` по образцу `af.env.example`.

```bash
docker compose --env-file af.env build
docker compose --env-file af.env up airflow-init
docker compose --env-file af.env up -d
```

В интерфейсе Airflow (`http://localhost:8080`) настройте:

- Connection `conn_pg` типа PostgreSQL с параметрами целевой базы.
- Connection `api_conn` типа HTTP с адресом учебного API.
- Pool `API_pool` на 1 слот и `postgres_pool` на 10 слотов.

Идентификаторы подключений задаются в `dags/data_models/api_pipeline_config.py`.
Пароли и локальные параметры подключения в репозиторий не включаются.

Сначала запустите `db_migrator`, затем включите `api_data_load`,
`datamarts_load` и `load_market_share`. Ежедневные DAG ограничены диапазоном
логических дат 01.06.2024–01.12.2024 включительно. При повторной обработке
уже существующих запусков отдельно проверьте состояние новых задач и историю
измерений SCD2. Скрипт `scripts/SQL_check_market_share.sql` возвращает
расхождения между витриной и агрегатами фактов; пустой результат означает,
что расхождений по проверяемому диапазону нет.

## Тесты

Для локального запуска используйте Python 3.12 и отдельное виртуальное окружение:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install apache-airflow==2.10.3 pytest==8.3.3 pytest-mock==3.14.0
pip install -r requirements.txt
docker compose --env-file af.env up -d postgrestest
export AIRFLOW_HOME="$PWD"
export PYTHONPATH="$PWD/dags:$PWD/tests"
python -m pytest -v -p no:cacheprovider tests
```

Тестовый PostgreSQL доступен на `localhost:5432`. Этот порт должен быть свободен
перед запуском нового контейнера. Для каждого набора интеграционных тестов
создаётся уникальная локальная база `aftest_*`, которая удаляется после теста.

Проверяются парсинг, вызов XCom, дедупликация, ограничение по дате,
исторический ключ города, обновление витрины и повторный расчёт.
